# معماری تفصیلی — فاز ۱

## تصمیم معماری
برنامه به‌صورت یک برنامه دسکتاپ محلی طراحی می‌شود. Qt فقط مسئول Presentation است؛ منطق مالی، چرخه عمر فاکتور، اعتبارسنجی و قواعد پرداخت در لایه‌های Domain/Application باقی می‌مانند. این تفکیک باید با تست‌های Go مستقل از Qt قابل اثبات باشد.

## لایه‌ها و مسئولیت‌ها
- **Domain:** موجودیت‌ها و قواعد خالص؛ بدون import از Qt، SQLite یا فایل‌سیستم.
- **Application:** موارد کاربرد، اعتبارسنجی سطح کاربرد و هماهنگی تراکنش‌ها؛ وابستگی به قراردادهای مورد نیاز، نه پیاده‌سازی جزئیات.
- **Storage adapter:** SQLite، migrationها و تراکنش‌ها. هر اتصال باید Foreign Key را فعال کند؛ سیاست journal و busy timeout پس از تست تعیین می‌شود.
- **Presentation adapter:** پنجره‌ها، فرم‌ها، نمایش خطا، RTL و تبدیل ورودی/خروجی UI. هیچ محاسبه مالی در callbackهای Qt قرار نمی‌گیرد.
- **Export adapters:** PDF و XLSX مدل سند و محاسبات مشترک را مصرف می‌کنند.
- **Platform/deployment:** مسیر داده کاربر، فایل‌های Qt زمان اجرا، logging حداقلی و Installer.

## جریان درخواست
Qt widget → Presentation handler → Application use case → Domain validation → Repository/transaction → نتیجه کاربرد → نمایش وضعیت یا پیش‌نمایش.
برای PDF و XLSX، جریان از مدل سند معتبر و نتیجه محاسبه‌شده آغاز می‌شود؛ خروجی‌ها حق محاسبه مجدد مجموع را ندارند.

## ساختار پیشنهادی
این ساختار به‌تدریج و بر اساس کد واقعی ایجاد خواهد شد:
- cmd/qt-prototype/ — نمونه مستقل اتصال
- cmd/invoice-maker/ — ورودی برنامه اصلی (پس از تثبیت معماری)
- internal/domain/
- internal/application/
- internal/adapters/sqlite/
- internal/adapters/pdf/
- internal/adapters/xlsx/
- internal/adapters/calendar/
- internal/presentation/qt/
- migrations/
- docs/

از ایجاد Interface برای هر نوع یا تابع خودداری شود. قرارداد فقط در مرزهایی تعریف شود که نیاز به جداسازی، تست جایگزین یا تعویض آداپتر وجود دارد.

## انتخاب اولیه Binding
MIQT انتخاب آزمایشی فاز ۱ است: API مبتنی بر Qt 6 و CGO، Binding دارای مجوز MIT و پشتیبانی اعلام‌شده برای Windows. نسخه ماژول در go.mod پین می‌شود. این انتخاب نهایی نیست؛ نیازمند Build و اجرای موفق با Qt 6.12 و MinGW واقعی پروژه است.

## مدیریت رشته و RTL
MIQT رشته‌های Go را به QString با UTF-8 تبدیل می‌کند؛ متن‌های ورودی/خروجی باید UTF-8 معتبر باشند. جهت RTL برای نمونه فعال شده است، اما این موضوع جایگزین تست متن ترکیبی فارسی/لاتین، اعداد، ورودی صفحه‌کلید و PDF نیست.

## ملاحظات Threading
Qt انتظار دارد اشیای GUI در thread اصلی ساخته و استفاده شوند. نمونه فعلی همه تعاملات را در callback رویداد Qt نگه می‌دارد. هر کار پس‌زمینه آینده باید نتیجه را از مسیر امن به thread رابط کاربری منتقل کند.

## داده و مالی
مبالغ با integer در واحد قراردادی پول ذخیره می‌شوند؛ مقادیر محاسباتی، قواعد گردکردن، مالیات و تخفیف در Domain تعریف و با تست مرزی پوشش داده می‌شوند. ذخیره‌سازی، شماره‌گذاری و تخصیص پرداخت باید تراکنشی باشد.

## معیار بازبینی معماری
- Domain بدون وابستگی Qt قابل تست باشد.
- UI فاقد منطق محاسباتی مالی باشد.
- خروجی‌ها از یک مدل داده مشترک استفاده کنند.
- تغییر تنظیمات جاری، Snapshot اسناد قدیمی را تغییر ندهد.
- خطاهای storage به خطاهای کاربردی قابل نمایش تبدیل شوند، بدون افشای داده حساس.
