# پشتیبان‌گیری و بازیابی

## سیاست داده

دیتابیس فعال در مسیر محلی کاربر، زیر `%LOCALAPPDATA%\invoice-maker\invoice-maker.db` قرار می‌گیرد. پوشه Hidden فقط برای کاهش احتمال حذف تصادفی است و مانع حذف عمدی، خرابی دیسک یا بدافزار نمی‌شود.

## قواعد لازم برای پیاده‌سازی Backup/Restore

- هنگام پشتیبان‌گیری از API پشتیبان SQLite یا روش سازگار با WAL استفاده شود؛ کپی‌کردن صرف فایل اصلی در حالی که برنامه باز است قابل اتکا نیست.
- فایل پشتیبان ابتدا در فایل موقت نوشته، سپس با موفقیت اعتبارسنجی و به مقصد نهایی منتقل شود.
- قبل از Restore، دیتابیس جاری و فایل مقصد اعتبارسنجی شوند؛ بازیابی باید با نسخه schema سازگار باشد.
- پیش از Restore از دیتابیس فعلی نسخه پشتیبان خودکار تهیه شود.
- مسیر مقصد به انتخاب کاربر باشد و عملیات overwrite با تأیید صریح انجام شود.
- پس از Restore، integrity check و foreign_key_check اجرا شود.
- پایان لایسنس نباید دسترسی کاربر به داده‌های خود را مسدود کند.

## وضعیت فاز ۲

سیاست و مسیر داده مستند شده‌اند، اما قابلیت عملیاتی Backup/Restore هنوز پیاده‌سازی نشده و نباید به‌عنوان قابلیت آماده محصول معرفی شود.
