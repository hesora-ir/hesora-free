# امنیت و مدل تهدید

## اصول
- داده‌های فاکتور و مشتری محلی باقی می‌مانند و به اعتبار لایسنس وابسته نیستند.
- کلید خصوصی امضای لایسنس خارج از برنامه مشتری نگهداری می‌شود.
- اطلاعات شخصی و بانکی نباید در Log یا telemetry ثبت شوند.
- مجوز قابلیت‌ها در لایه Application بررسی می‌شود؛ کنترل UI فقط برای تجربه کاربری است.
- ورودی توکن و claims باید قبل از اعطای قابلیت اعتبارسنجی شوند.

## مدل تهدید لایسنس
امضای Ed25519 از جعل claims بدون کلید خصوصی جلوگیری می‌کند، اما در برابر Patch شدن برنامه توسط مهاجم دارای دسترسی کامل به دستگاه، تغییر ساعت سیستم یا حذف شناسه نصب تضمین نمی‌دهد. لایسنس آفلاین نباید به‌عنوان DRM غیرقابل دورزدن توصیف شود.

## فایل‌های محلی
توکن و شناسه نصب در دایرکتوری داده برنامه ذخیره می‌شوند؛ فایل‌ها با نوشتن اتمی و مجوز محدود ایجاد می‌شوند. این مجوزها روی Windows تضمین امنیتی معادل ACL سفارشی نیستند و باید نصب/دسترسی با حساب‌های Windows آزمایش شود. فایل SQLite کاربر نباید در زمان انقضا، حذف لایسنس یا خرابی توکن پاک یا قفل شود.

## موارد باز پیش از انتشار
- بازبینی وابستگی‌ها و مجوزهای آن‌ها
- آزمایش دستکاری/جعل توکن و تغییر ساعت
- آزمون ACL و محل داده در Windows
- تعریف فرآیند صدور، لغو، تمدید و چرخش کلید
- طراحی پیام‌های خطای بدون افشای داده حساس
- بازبینی امنیتی مستقل و تست یکپارچه‌سازی UI/Application
