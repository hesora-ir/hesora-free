# سیستم قالب، سربرگ و پیش‌نمایش

## اجزا
- `DocumentTemplate`: اندازه صفحه A4/Letter، حالت عمودی/افقی، فونت، اندازه متن، رنگ اصلی/تأکیدی، سربرگ انتخابی، حساب‌های بانکی منتخب، متن پایانی و تنظیمات نمایش مالیات/اطلاعات پرداخت؛ PNG/JPEG لوگو، مهر و امضا در فیلدهای data URI.
- `Letterhead`: عنوان، زیرعنوان، مسیر محلی لوگو و خط اطلاعات تماس؛ قابلیت اتصال به پروفایل صادرکننده دارد.
- `BankAccount`: نام بانک، صاحب حساب، شماره حساب، کارت و شبا؛ حساب‌ها در پایگاه داده محلی ذخیره می‌شوند.
- `template_bank_accounts`: ترتیب حساب‌های بانکی مرتبط با هر قالب را ثبت می‌کند.
- `internal/render/html`: HTML پیش‌نمایش را از مدل سند، اقلام و خروجی مشترک محاسبات مالی تولید می‌کند.

## قواعد امنیت و صحت
- نام فونت و رنگ‌ها اعتبارسنجی می‌شوند؛ رنگ فقط به صورت #RRGGBB پذیرفته می‌شود.
- تصویرها فقط PNG/JPEG با سقف ۵۰۰ کیلوبایت و ابعاد ۳۰۰۰×۳۰۰۰ پذیرفته می‌شوند؛ SVG و URL راه دور رد می‌شوند.
- محتوای مشتری، صادرکننده، شرح قلم، یادداشت و اطلاعات بانکی پیش از درج در HTML escape می‌شود.
- مسیر لوگو باید مسیر محلی انتخاب‌شده توسط کاربر باشد؛ URLهای راه دور در رندر لوگو پذیرفته نمی‌شوند.
- مبلغ‌ها در renderer دوباره محاسبه مستقل نمی‌شوند؛ جمع‌ها از `domain.CalculateFinancials` گرفته می‌شوند و مبلغ هر قلم از `InvoiceItem.LineTotal`.
- اسناد از snapshot مشتری و صادرکننده استفاده می‌کنند تا تغییر پروفایل فعلی، اطلاعات تاریخی سند را تغییر ندهد.

## ذخیره‌سازی
Migration شمارهٔ ۴ جدول‌های `issuer_letterheads`، `bank_accounts`، `document_templates` و `template_bank_accounts` را اضافه می‌کند؛ migration شمارهٔ ۱۶ تصویرهای قالب را به SQLite می‌افزاید. حساب‌های بانکی و سربرگ‌ها به صورت رکوردهای مستقل هستند؛ هر قالب می‌تواند به یک سربرگ و چند حساب بانکی متصل شود.

## وضعیت و محدودیت‌ها
- UI Qt ساخت/ویرایش قالب Pro، انتخاب/حذف تصویرها و پیش‌نمایش HTML را دارد؛ build محلی ویندوز انجام شده است.
- تست دامنه و SQLite تصویرها را اعتبارسنجی و ماندگاری‌شان را بررسی می‌کند؛ PDF تستی وجود تصویر تعبیه‌شده را نیز می‌سنجد.
- تصویرهای قالب از طریق فید ابری دوطرفه منتقل می‌شوند. تغییر فیلدهای مستقل بر پایهٔ snapshot مشترک ادغام می‌شوند؛ در تعارض هم‌فیلدی پس از رضایت کاربر مقدار دسکتاپ می‌ماند. برای نگاشت‌های قدیمیِ فاقد snapshot، نخستین تعارض با همان سیاست desktop-wins حل می‌شود.
- بازبینی دستی چیدمان تصویر، صفحه‌بندی و حروف فارسی در Windows همچنان لازم است.
- تبدیل تاریخ جلالی/ارقام فارسی و صفحه‌بندی چندصفحه‌ای آزمون خودکار دارند؛ بازبینی چیدمان و شکل‌دهی فارسی روی Windows هنوز دستی انجام نشده است.
