# اتصال نسخهٔ رایگان به وب هسورا

## فعال‌سازی لایسنس صادرشده

کاربر در وب‌سایت حساب می‌سازد و کد خریداری‌شده به حسابش تحویل می‌شود. او فقط کد را در تنظیمات برنامه وارد می‌کند. برنامه کلید عمومی را از `GET /api/v1/licenses/public-key` روی HTTPS دریافت می‌کند و با `POST /api/v1/licenses/activate` همان کد را به شناسهٔ نصب داخلی خود متصل می‌کند. کد یک‌بارمصرف می‌شود و توکن امضاشدهٔ مخصوص نصب برای استفادهٔ آفلاین ذخیره می‌شود. شناسهٔ نصب از کاربر کپی یا درخواست نمی‌شود. کلید خصوصی فقط روی سرور می‌ماند؛ build، متغیر محیطی و تحویل دستی کلید عمومی به مشتری لازم نیست.

## مدیریت بکاپ از دسکتاپ

در تنظیمات، پس از ورود به حساب ابری و تازه‌سازی فهرست، شناسهٔ بکاپ در کنار نام و زمان ساخت آن نمایش داده می‌شود. شناسه را در کادر عملیات وارد کنید تا نسخهٔ بکاپ دانلود یا پس از تأیید حذف شود. برنامه پیش از نهایی‌کردن فایل دانلودی، SHA-256 پاسخ سرور را بررسی می‌کند. بازیابی از پنل وب انجام می‌شود؛ دانلود فایل به‌تنهایی بانک اطلاعاتی باز برنامه را تغییر نمی‌دهد.

سرویس متناظر PHP 8.4 در پروژهٔ `hesora-web` قرار دارد. نشانی تولید `https://hesora.ir` است. برای ارسال رمز، لایسنس و داده از HTTP عمومی استفاده نمی‌شود. HTTP فقط روی loopback برای توسعه پذیرفته است.

## استفاده در برنامه

در تنظیمات، بخش «بکاپ و اتصال به فضای ابری»:

1. برای ساخت حساب، «ساخت حساب فقط در وب‌سایت Hesora» را بزنید؛ ثبت‌نام فقط در صفحهٔ وب انجام می‌شود و برنامه فرم ثبت‌نام ندارد.
2. پس از فعال‌سازی لایسنس، برنامه با همان مجوز به‌صورت خودکار به حساب وب وصل می‌شود؛ ورود ایمیل و رمز در برنامه لازم نیست. برای حساب‌های بدون لایسنس، ورود دستی وب همچنان در دسترس است.
3. کد خریداری‌شده را در «فعال‌سازی لایسنس پرو» وارد کنید. برنامه کلید عمومی را دریافت، کد را آنلاین فعال و شناسهٔ نصب را خودکار ثبت می‌کند.
5. «بکاپ‌گیری ابری» snapshot سازگار با WAL می‌سازد، سلامت آن را بررسی و همراه SHA256 ارسال می‌کند. فهرست، دانلود و حذف از دسکتاپ و پنل وب در دسترس است.
6. «ذخیره بکاپ روی حافظه کامپیوتر» بدون ورود و اشتراک قابل استفاده است. مقصد باید فایل جدید باشد؛ برای حفاظت از اطلاعات، فایل موجود بازنویسی نمی‌شود.

سقف سرویس اولیه برای هر حساب: ۲۰ بکاپ، هرکدام ۵۰ MiB و مجموع ۲۵۰ MiB. بکاپ ابری برای حساب رایگان دارای خدمات ابری نیز قابل استفاده است. دانلود بکاپ‌های قبلی با انقضای Pro بسته نمی‌شود.

## دریافت و نگهداری کلید عمومی

کلاینت کلید عمومی را از endpoint فقط روی HTTPS می‌گیرد، اندازه و قالب Ed25519 را اعتبارسنجی می‌کند و آن را کنار توکن محلی با دسترسی محدود ذخیره می‌کند. build بدون کلید معتبر هم می‌تواند کد را آنلاین فعال کند؛ پس از اولین فعال‌سازی، امضا و انقضا آفلاین هم بررسی می‌شود. در صورت تغییر کلید سرور، برنامه باید با توکن‌های تازه یا سازوکار چرخش کلید سازگار شود؛ کلید خصوصی به هیچ build یا دستگاه مشتری داده نمی‌شود.

## قرارداد و محدودیت‌ها

کلاینت `internal/cloud` از `/api/v1/auth/login`، `/api/v1/auth/device-login`، `/licenses/public-key`، `/licenses/activate`، `/me`، `/licenses/validate`، `/backups` و `/cloud/documents` استفاده می‌کند. درخواست‌های شبکه و snapshot در goroutine اجرا می‌شوند و نتیجه روی نخ رابط Qt اعمال می‌شود. نشست دستگاه ۳۰ روز اعتبار دارد و در شروع بعدی برنامه با لایسنس فعال تمدید می‌شود.

API اسناد، نسخه‌گذاری خوش‌بینانه و tombstone دارد؛ نوشتن نیازمند Pro است. هنوز همگام‌سازی خودکار جداول حسابداری و رابط حل تعارض ارائه نمی‌شود. بکاپ ابری یک snapshot کامل پایگاه داده است و با همگام‌سازی رکوردی تفاوت دارد. بازیابی خودکار روی پایگاه دادهٔ باز برنامه نیز وجود ندارد؛ فایل دانلودی را بدون نگهداری نسخهٔ فعلی روی اطلاعات فعال جایگزین نکنید.

لغو سرور با «بررسی آنلاین اعتبار لایسنس» در برنامه اعمال می‌شود. اعتبار آفلاین تا تاریخ پایان امضا قابل بررسی است؛ لغو فوری در قطع اینترنت تضمین نمی‌شود. انقضا محدودیت‌های رایگان را برمی‌گرداند و داده را حذف نمی‌کند.

## آزمون

```powershell
go test ./internal/...
go vet ./internal/...
# از ریشهٔ پروژهٔ وب؛ پایگاه داده و سرور موقت:
# ابتدا اتصال MySQL و Redis آزمایشی را طبق docs/OPERATIONS.md پروژهٔ وب تنظیم کنید.
$env:HESORA_DESKTOP_DIR = 'C:\Users\hessam\Documents\GitHub\hesora-free'
python tests/http_test.py
```

تست `TestPHPContract` ورود واقعی Go به PHP، پذیرش امضای لایسنس PHP توسط Go، snapshot، آپلود و دریافت متادیتای بکاپ و API سند را بررسی می‌کند.

اصلاح شبا شامل ارقام فارسی/عربی، پیشوند IR، فاصله و نشانه‌های جهت متن است. checksum معتبر بازنویسی یا حدس زده نمی‌شود. در خروجی‌های قدیمی نام بانک از شبای معتبر استخراج می‌شود، اما نام ثبت‌شدهٔ تاریخی حفظ می‌شود.
