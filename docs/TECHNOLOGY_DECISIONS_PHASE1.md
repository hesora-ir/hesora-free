# تصمیم فناوری فاز ۱ — Go و Qt

## تصمیم آزمایشی
برای نمونه اولیه، MIQT نسخه ماژول `v0.15.0` بررسی می‌شود. مسیر import Qt 6 آن `github.com/mappu/miqt/qt6` است. پروژه MIQT خود را Binding برای Qt 5.15 و Qt 6.4+ معرفی می‌کند و Windows x86_64 را در پلتفرم‌های پشتیبانی‌شده فهرست می‌کند.

## دلیل انتخاب برای نمونه
- استفاده از Qt Widgets به‌جای محدودشدن به QML
- فراخوانی مستقیم Qt از طریق CGO، بدون سرویس helper مستقل در زمان اجرا
- مجوز MIT برای خود Binding
- API نزدیک به کلاس‌های اصلی Qt و نمونه‌های قابل بررسی

## محدودیت‌ها و ریسک‌ها
1. اعلام پشتیبانی Qt 6.4+ به‌تنهایی اثبات Build روی Qt 6.12 نیست.
2. راهنمای MIQT برای Windows چند مسیر متفاوت دارد؛ بعضی آزمایش‌های اعلام‌شده با Qt 5.15/Clang یا MSYS2/Qt 6.7 انجام شده‌اند، نه دقیقاً با نصب Qt 6.12 پروژه.
3. CGO به compiler و linker سازگار با Qt نیاز دارد. نباید فرض شود هر MinGW یا MSVC با هر بسته Qt سازگار است.
4. وابستگی‌های Qt و pluginهای پلتفرم باید در Installer توزیع شوند.
5. MIT بودن MIQT، مجوز Qt را تغییر نمی‌دهد. انتخاب LGPL یا تجاری و شیوه لینک/توزیع باید جداگانه بررسی حقوقی شود.
6. Binding می‌تواند از نظر پوشش API یا بلوغ محدودیت داشته باشد؛ فقط APIهای استفاده‌شده در نمونه و ماژول‌های موردنیاز باید آزمایش شوند.

## معیار تصمیم نهایی
MIQT فقط در صورت موفقیت Build و اجرای نمونه با Qt 6.12 و toolchain واقعی، بررسی مجوزهای توزیع و ثبت فرایند بازتولیدپذیر برای ادامه انتخاب می‌شود. در غیر این صورت گزینه‌های جایگزین با نمونه عملی و مقایسه نگهداری/مجوز بررسی خواهند شد.
