## درباره هسورا

**Hesora (هسورا)** یک نرم‌افزار دسکتاپ فارسی برای مدیریت مشتریان، صدور فاکتور و پیش‌فاکتور، پیگیری پرداخت‌ها و مانده‌حساب‌ها و تهیه خروجی‌های تجاری است. برنامه با تمرکز بر تجربه فارسی و راست‌چین، نگهداری محلی اطلاعات و محاسبات مالی طراحی شده است.

هسورا برای کسب‌وکارهایی ساخته شده که می‌خواهند بدون وابستگی دائمی به اینترنت، اطلاعات مشتریان و اسناد مالی خود را روی رایانه مدیریت کنند و در صورت نیاز از سرویس‌های آنلاین Hesora Pro و فضای ابری استفاده کنند.

- **وب‌سایت:** [hesora.ir](https://hesora.ir)
- **مخزن نسخه رایگان:** [GitHub](https://github.com/hesora-ir/hesora-free)
- **سیستم‌عامل هدف:** Windows 10 و Windows 11 در نسخه‌های پشتیبانی‌شده
- **زبان رابط:** فارسی و راست‌چین (RTL)
- **ذخیره‌سازی:** SQLite محلی

> وضعیت پروژه: مخزن شامل هسته Go، رابط Qt، ذخیره‌سازی SQLite، ماژول‌های مالی، خروجی و اتصال وب است. برخی مسیرهای رابط کاربری و انتشار همچنان نیازمند آزمون نهایی روی Windows هستند. وجود کد یا تست در مخزن به‌تنهایی به معنی تأیید انتشار تجاری نیست.

- کنترل تخصیص تکراری یا بیش از مانده در قواعد دامنه

> وضعیت دقیق گردش پرداخت در رابط کاربری و مسیرهای بازپرداخت/ابطال باید پیش از انتشار نهایی آزموده شود. برای جزئیات به [چرخه عمر فاکتور و پرداخت](docs/INVOICE_LIFECYCLE.md) مراجعه کنید.

> طبق [وضعیت فعلی شاخه main](docs/ROADMAP_CURRENT.md)، بخشی از شاخص‌های داشبورد یا جریان‌های UI ممکن است هنوز نمایشی یا در حال تکمیل باشند. اعداد را بدون تطبیق با اسناد و گزارش‌های اصلی، مبنای تصمیم‌گیری مالیاتی یا حسابداری قرار ندهید.

### 📄 خروجی و قالب اسناد
- ماژول تولید PDF
- ماژول تولید Excel با فرمت XLSX
- خروجی مشترک بر پایه مدل سند و محاسبات مالی
- حفظ واحد پول سند در خروجی
- استفاده از اطلاعات صادرکننده، مشتری و حساب بانکی ذخیره‌شده در Snapshot

**وضعیت تأیید:** ماژول‌های PDF و XLSX در مخزن وجود دارند؛ اما شکل‌دهی فارسی/RTL، فونت، لوگو، صفحه‌بندی و چاپ باید روی Windows و برنامه‌های مقصد مانند Excel و LibreOffice به‌صورت بصری آزموده شوند. اتصال و دسترسی همه خروجی‌ها از UI نیز باید در نسخه منتشرشده بررسی شود.

### ⚙️ تنظیمات برنامه
- انتخاب فونت رابط و اندازه آن
- تم روشن و تیره
- انتخاب واحد پول پیش‌فرض (ریال یا تومان)
- انتخاب آیکون برنامه
- تنظیمات محلی و وضعیت مجوز
- تنظیمات اتصال به حساب و فضای ابری در نسخه‌های مربوط

### ☁️ اتصال وب و پشتیبان‌گیری
Hesora Pro در کنار برنامه دسکتاپ، سرویس وب و قابلیت‌های حساب کاربری را ارائه می‌کند. بر اساس مستندات اتصال وب:

- ثبت‌نام حساب از طریق وب‌سایت Hesora
- فعال‌سازی کد لایسنس از طریق HTTPS
- اعتبارسنجی امضای لایسنس با Ed25519
- ذخیره توکن امضاشده برای اعتبارسنجی آفلاین
- ایجاد بکاپ محلی بدون نیاز به اشتراک
- بارگذاری، فهرست‌کردن، دانلود و حذف بکاپ‌های ابری
- بررسی SHA-256 فایل دریافت‌شده
- مدیریت بکاپ‌ها از دسکتاپ و پنل وب

بکاپ ابری یک Snapshot از پایگاه داده است و با همگام‌سازی پیوسته فرق دارد. همگام‌سازی افزایشی اسناد و دریافت‌ها و ادغام فیلدی تغییرهای مستقل پیاده‌سازی شده‌اند؛ در تعارض هم‌فیلدی، پس از تأیید کاربر مقدار دسکتاپ انتخاب می‌شود. همگام‌سازی همهٔ جدول‌های حسابداری (از جمله هزینه‌ها و دفترکل) هنوز کامل نیست. دانلود فایل بکاپ به‌تنهایی پایگاه دادهٔ باز برنامه را جایگزین نمی‌کند؛ بازیابی باید طبق راهنمای سرویس انجام شود.

## نسخه رایگان و Hesora Pro

هسورا با مدل رایگان و Pro طراحی شده است. نسخه رایگان برای شروع و استفاده پایه مناسب است؛ Pro محدودیت‌های ظرفیت را افزایش می‌دهد و خدمات پیشرفته و آنلاین را فعال می‌کند.

| قابلیت | Hesora Free | Hesora Pro |
|---|---|---|
| مدیریت پایه مشتریان | ✅ | ✅ |
| ایجاد و مشاهده فاکتور پایه | ✅ | ✅ |
| تعداد فروشگاه / پروفایل صادرکننده | ۱ فروشگاه | نامحدود طبق جدول داخل برنامه |
| سقف مشتری | ۵۰ مشتری | نامحدود طبق جدول داخل برنامه |
| سقف فاکتور | ۲۰۰ فاکتور | نامحدود طبق جدول داخل برنامه |
| قالب فاکتور | قالب استاندارد Hesora | قالب‌ها و سربرگ‌های سفارشی |
| فونت رابط | انتخاب محدود | مجموعه فونت‌های بیشتر |
| خروجی PDF پیشرفته | محدود/نیازمند مجوز | قابلیت پیشرفته |
| خروجی Excel پیشرفته | محدود/نیازمند مجوز | قابلیت پیشرفته |
| قابلیت‌های پیشرفته پرداخت | پایه | دسترسی به قابلیت‌های پیشرفته |
| پشتیبان‌گیری محلی | ✅ | ✅ |
| خدمات بکاپ ابری | طبق سیاست حساب/سرویس | ✅ |
| حساب و سرویس‌های وب Hesora | محدود | ✅ |
| مشاهده اسناد در وب | ندارد | در محدوده سرویس و پلن فعال |
| اعلان‌ها و دریافت آخرین تغییرات | محدود/در دست توسعه | در برنامه سرویس Pro |

**مهم:** جزئیات قیمت، مدت اشتراک، تعداد دستگاه مجاز و شرایط تمدید را از [وب‌سایت رسمی Hesora](https://hesora.ir) بررسی کنید. جدول داخل برنامه و سیاست پلن فعال، مرجع نهایی محدودیت‌های حساب است.

### محدودیت‌های نسخه رایگان
- یک فروشگاه
- حداکثر ۵۰ مشتری
- حداکثر ۲۰۰ فاکتور
- قالب استاندارد Hesora
- تعداد محدود فونت‌های رابط

### امکانات پیشرفته Pro
- افزایش ظرفیت فروشگاه، مشتری و فاکتور
- قالب و سربرگ سفارشی
- دسترسی به فونت‌های بیشتر
- قابلیت‌های پیشرفته PDF و Excel
- امکانات پیشرفته پرداخت
- سرویس‌های وب و مدیریت حساب
- مدیریت بکاپ ابری
- دسترسی به API اسناد ابری مطابق سطح دسترسی پلن

### فعال‌سازی Pro
1. در وب‌سایت [hesora.ir](https://hesora.ir) حساب کاربری بسازید.
2. پس از تهیه لایسنس، کد فعال‌سازی را دریافت کنید.
3. در برنامه به بخش **تنظیمات ← مجوز نرم‌افزار** بروید.
4. کد لایسنس را وارد و فعال‌سازی را انجام دهید.
5. وضعیت مجوز و اتصال حساب را در همان بخش بررسی کنید.

کلید خصوصی امضای لایسنس روی سرور نگهداری می‌شود و برنامه با کلید عمومی، توکن امضاشده را بررسی می‌کند. لایسنس آفلاین تا زمان اعتبار قابل ارزیابی است؛ لغو فوری در زمان قطع اینترنت تضمین نمی‌شود.

## حریم خصوصی و مالکیت داده

- پایگاه داده اصلی به‌صورت محلی و با SQLite نگهداری می‌شود.
- مسیر داده برنامه در Windows در پوشه محلی کاربر، زیر مسیر `%LOCALAPPDATA%\invoice-maker` تعریف شده است.
- داده‌های کاربر داخل پوشه نصب برنامه قرار نمی‌گیرند.
- تغییر یا انقضای مجوز نباید دسترسی به داده‌های شخصی و مالی کاربر را مسدود کند.
- اطلاعات حساس بانکی و تماس نباید در Log ثبت شوند.
- Snapshot مشتری و صادرکننده باعث می‌شود تغییر مشخصات فعلی، اطلاعات تاریخی فاکتورهای قبلی را بازنویسی نکند.
- استفاده از سرویس‌های ابری مستلزم ارسال داده به سرور است؛ پیش از استفاده، سیاست حریم خصوصی و شرایط سرویس را مطالعه کنید.

**توصیه:** همیشه علاوه بر بکاپ ابری، نسخه پشتیبان محلی در یک حافظه یا محل امن مستقل نگهداری کنید.

## نصب و اجرا

### دریافت نسخه آماده
برای دریافت نسخه‌های منتشرشده و فایل نصب، بخش Releases مخزن را بررسی کنید:

[مشاهده نسخه‌های منتشرشده در GitHub](https://github.com/hesora-ir/hesora-free/releases)

اگر هنوز Release رسمی منتشر نشده باشد، می‌توانید برنامه را از سورس و طبق مراحل زیر بسازید.

### پیش‌نیازهای توسعه
- Windows x64
- Go سازگار با نسخه درج‌شده در `go.mod` (در مستندات فعلی Go 1.25.1)
- Qt 6.12.0 برای MinGW
- MinGW سازگار با Qt انتخاب‌شده
- CMake نسخه 3.25 یا بالاتر (برای مسیر CMake)
- WiX Toolset 6.0.2 و .NET SDK (برای ساخت MSI)

### اجرای توسعه‌ای سریع
در PowerShell و از ریشه مخزن:

```powershell
.\dev.ps1
```

برای Build و اجرا بدون اجرای دوباره تست‌ها:

```powershell
.\dev.ps1 -SkipChecks
```

برای اجرای تست‌ها و Build بدون بازکردن پنجره برنامه:

```powershell
.\dev.ps1 -NoRun
```

راهنمای کامل و مسیرهای ابزارها در [docs/BUILD_AND_RUN.md](docs/BUILD_AND_RUN.md) آمده است.

### اجرای تست‌ها
```powershell
go test ./...
go vet ./...
gofmt -l .
```

### ساخت نصب‌کننده
```powershell
.\scripts\build-installer.ps1
```

خروجی MSI و مسیرهای مورد انتظار در [راهنمای ساخت و اجرا](docs/BUILD_AND_RUN.md) توضیح داده شده‌اند. ساخت و نصب MSI باید روی محیط Windows تمیز نیز آزمایش شود.

## مشارکت در توسعه

از پیشنهاد قابلیت جدید، گزارش خطا و مشارکت در توسعه استقبال می‌شود.

1. ابتدا Issue مرتبط را بررسی یا یک Issue جدید ثبت کنید.
2. برای هر تغییر، یک Branch مستقل از آخرین `main` بسازید.
3. تغییرات را همراه تست و مستندات لازم انجام دهید.
4. خروجی تست‌ها و محدودیت‌های شناخته‌شده را در Pull Request بنویسید.
5. Pull Request را برای بازبینی ارسال کنید.

لطفاً تغییرات مربوط به محاسبات مالی، Migrationهای SQLite، Snapshot اسناد و لایسنس را همراه تست‌های مربوط ارائه کنید. Migrationهای منتشرشده را به‌جای ویرایش، با Migration جدید اصلاح کنید.

## وضعیت توسعه

وضعیت شاخه `main`، قابلیت‌های پیاده‌سازی‌شده و کارهای باقی‌مانده در [docs/ROADMAP_CURRENT.md](docs/ROADMAP_CURRENT.md) نگهداری می‌شود. موارد زیر باید پیش از اعلام نسخه پایدار نهایی آزموده شوند:

- Build و اجرای واقعی رابط Qt روی Windows پشتیبانی‌شده
- گردش کامل مشتری تا صدور فاکتور و ثبت پرداخت
- صحت نمایش فارسی و RTL در PDF و Excel
- صفحه‌بندی و چاپ اسناد
- نصب، ارتقا و حذف MSI و حفظ داده کاربر
- Backup و Restore و اعتبارسنجی بازیابی
- اتصال سرویس وب و سناریوهای فعال‌سازی/انقضای لایسنس

#### همگام‌سازی دریافت‌های فضای وب

همگام‌سازی افزایشی فاکتورها، دریافت‌ها و ابطال‌های ثبت‌شدهٔ وب را به جداول بومی SQLite اعمال می‌کند؛ ارسال تغییرات دسکتاپ نیز اختیاری و خودکار است. شناسه‌های دریافت پایدارند؛ ردیف و تخصیص دریافت باطل‌شده نگهداری می‌شوند و فقط از مانده‌ها/داشبورد کنار می‌روند. تعارض فیلدهای مستقل سه‌طرفه ادغام می‌شود و تعارض هم‌فیلدی طبق سیاست تأییدشدهٔ desktop-wins حل می‌شود. همگام‌سازی کامل همهٔ جدول‌های حسابداری و حل تعارض با انتخاب جداگانهٔ هر فیلد هنوز وجود ندارد.
